# External CH341 receiver recovery-access references

Date: 2026-10-09. AI assistance follows the [project README disclosure](../../README.md#ai-assistance-disclosure). This is research and a proposed investigation, followed by the explicitly recorded USB checks and isolated-adapter measurements below. No Monitor flash was programmed.

## Evidence and identification boundary

The [built-in USB preflight](receiver-usb-preflight-20261009.md) read receiver JEDEC `EF4014`, status `05h/35h = 00/00`, two all-`FF` SFDP responses and two matching 1,048,576-byte arrays. Original receiver SHA-256: `fb35263f0bc62cc1a43889da4313af3ace756c086aad8ef69d4bc6ed515b4055`. These observations do not identify the package/suffix or establish external recovery. See the [capacity reference](monitor-flash-capacities.md).

Winbond **W25Q80DV Revision N**, pp.5–6, 17, 49, 53 and 67, documents `EF4014`, 1 MiB, a 2.7–3.6 V supply and multiple packages/orderings. Its SFDP command requires `5Ah`, three address bytes and eight dummy clocks; most Winbond SPI memories shipped after June 2011 support SFDP. An all-`FF` response contains no usable table. **Inference:** it cannot distinguish an older/non-SFDP variant from an unsuccessful SFDP transaction, establish a date code, or prove this chip lacks SFDP. The exact marking and package remain necessary. [Winbond datasheet](https://www.winbond.com/resource-files/W25Q80DV_revN_04242026%20Plus.pdf).

Subsequent sharp photographs strongly support the **W25Q80DVUXIE USON-8 2 × 3-mm** candidate through the manufacturer's abbreviated marking scheme. The user's marked corner suggests pin 1 at the lower left of the displayed photograph; the user confirmed pin 4 as ground and reported 3.3 V at pin 8. Dimensions, SPI mapping and actual adapter signal levels still require physical confirmation. See the [marking identification and measurements](receiver-flash-marking-20261009.md). These findings refine identification without validating external access or programming.

## External adapter enumeration

After the user reported connecting the external adapter following the instruction to leave the Monitor and all interconnecting wires disconnected, Windows PnP enumeration found exactly one matching WCH device: **USB-SERIAL CH341 (COM15)**, class `Ports`, status `OK`, VID `1A86`, PID **`5523`**. No `5512` device was present in that enumeration. This is consistent with the documented UART mode, rather than the synchronous/parallel mode used by the existing SPI transport. Only Windows device inventory was queried: no native handle was opened and no SPI or serial command was sent.

The raw inventory is preserved in private `artifacts/device-backups/20261009-202749-external-ch341-enumeration/enumeration.json` (2026-10-09 18:27:49 UTC). The next step is to identify the actual adapter's mode jumper and header labels from clear front/back photographs before changing its mode. COM15 is not a verified SPI flash interface. Do not send the Monitor-specific GPIO routing through this adapter or guess its jumper setting from the reference product image. Signal-level measurement remains necessary after mode selection.

The user subsequently reported reconnecting the adapter with its jumper set to SPI. Fresh Windows enumeration at 18:33:55 UTC found exactly one matching device: `USB-EPP/I2C... CH341A`, class `WCH`, status `OK`, VID/PID **`1A86:5512`**, on the same USB instance suffix. The documented mode change is corroborated by the changed product ID. A subsequent `monitor_usb_probe.py --identify-only` invocation successfully opened the device through the pinned installed x64 DLL, set bounded USB timeouts and read descriptor `12011001ff000208861a1255040300000001`; cleanup succeeded. Code inspection confirmed this branch performs no target selection, GPIO output or SPI transfer. Native USB access works in this mode; SPI functionality and electrical levels are not yet tested.

Both reports are retained in private `artifacts/device-backups/20261009-203355-external-ch341-spi-enumeration/` as `enumeration.json` and `descriptor.json`. Current next step: establish actual header/power labeling and measure the isolated adapter's supply and CS/SCK/MOSI levels before any Monitor connection. The earlier UART result is historical, not the adapter's current mode.

Subsequently, the user's sharp actual-board photo established the labeled SPI row, and native PicoScope 2205A capture succeeded. The [PicoScope measurement report](picoscope-external-adapter-20261009.md) records three switching MOSI captures at approximately 0.009/3.262 V, with observed extrema −0.082/+3.352 V, while the adapter was physically isolated according to the user. A separate bare-adapter transport issued fixed read bursts without Monitor GPIO routing. This supersedes the earlier statement that no SPI transaction had been sent. SCK, CS, adapter supply, loaded behavior and independent recovery remain unvalidated.

Later the same evening, SCK, CS0 and VDD were measured with the same isolated setup: 3.3 V levels on all three, SPI mode 0, CS0 held low for one ~2 ms assertion per 256-byte burst, VDD ≈3.26 V unloaded with the current jumper positions. The second SPI-row label is `VDD`, not `RD` as first transcribed. This completes step 2 below for the unloaded adapter, except a DMM cross-check of VDD and loaded behavior. See the [PicoScope report](picoscope-external-adapter-20261009.md).

User-reported (not Claude-measured), Monitor fully unpowered, adapter disconnected: DMM resistance between the receiver flash VCC and GND starts at about **2 kΩ and rises** after the leads are attached. **Inference:** the rising reading indicates the meter charging decoupling capacitance on the rail; the start value is not a steady-state resistance. An ohmmeter reading at low test voltage also cannot predict current drawn by unpowered ICs at 3.3 V, so it neither proves nor excludes back-powering the receiver CPU. Follow-up user report: the reading settles at about **4 kΩ**; with reversed leads at about **2.8 kΩ** after roughly 3 s. **Inference:** the polarity-dependent, kilohm-level value is typical of a rail shared with other ICs (supply clamp/ESD and substrate junctions), not of a flash-only net; a lone unpowered W25Q80 would normally read much higher. The flash VCC is therefore very likely part of a receiver 3.3 V rail. Supplying pin 8 from the adapter's VDD (≈3.26 V, unknown current capability) would probably power further receiver circuitry, possibly including the DM5680, which could then drive the SPI bus concurrently. **Do not connect the adapter's VDD to pin 8 in-circuit** until a current-limited test shows the rail current and confirms no SPI activity from the receiver side. Diode-test readings are pending.

User-reported continuity (photo of the 1R3 main board, 2026-10-09): the receiver flash VCC connects through to the `3V3` pin of the board's `DONE / 3V3 / GND / TDO / TDI / TCK / TMS` header (FPGA JTAG). The user reads this as the common onboard 3.3 V rail. **Consequence:** feeding flash pin 8 from any external source would back-power the whole board's 3.3 V net, including the FPGA, the MStar and the DM5680 region, far beyond what the breakout's VDD output is known to supply, with partial boot and SPI contention as likely outcomes. **External in-circuit access with programmer-supplied VCC is ruled out for this board.** Remaining routes: (a) the Monitor's built-in, hardware-routed CH341 path (GPIO bus selection, independent of receiver firmware contents; already read twice), (b) external SPI with the Monitor self-powered, which requires a validated way to hold the DM5680 off the bus (none known), or (c) desoldering the USON flash for off-board access (invasive, separate hardware decision).

## Conditional pin map

For the documented **8-pin SOIC / 8-pad WSON or USON** layout, viewed from above with pin 1 established:

| Flash pin | Function | External SPI connection |
|---:|---|---|
| 1 | `/CS` | Verified chip-select output |
| 2 | `DO / IO1` | MISO input |
| 3 | `/WP / IO2` | Datasheet-correct inactive level |
| 4 | GND | Common ground |
| 5 | `DI / IO0` | MOSI output |
| 6 | CLK | SCK output |
| 7 | `/HOLD / IO3`; some package drawings allow `/RESET` | Datasheet-correct inactive level |
| 8 | VCC | One verified compatible supply |

This is a reference, not confirmed Monitor wiring. WLCSP uses ball coordinates instead. Do not hard-strap pins 3 or 7 to VCC until existing board drivers and the actual part are understood. [Winbond package and pin descriptions, pp.6–9](https://www.winbond.com/resource-files/W25Q80DV_revN_04242026%20Plus.pdf#page=6).

WCH documents the CH341A/B/F four-wire master interface as `DIN/MISO = pin 22 (D7)`, `DOUT/MOSI = 20 (D5)`, `DCK/SCK = 18 (D3)`, and `CS0/CS1/CS2 = 15/16/17 (D0/D1/D2)`. Those are CH341 silicon pins, not a breakout header numbering scheme. Default synchronous/parallel USB mode is PID `5512`; default UART mode is `5523`. Board mode selection must be confirmed; a power jumper does not establish SPI mode. WCH supports both 5 V and 3.3 V chip supplies. [WCH official catalogue](https://www.wch-ic.com/downloads/CH341DS1_PDF.html), [manufacturer-authored CH341DS1 v3C, §§4.6, 5.2–5.3, pp.7–9, mirrored PDF](https://www.eliptor.pl/pub/pdf/Winchiphead/CH341DS1.PDF#page=7). Exact transport clock setup still requires review.

## Next physical investigation

1. Record sharp receiver flash marking/pin-1 photographs and the adapter's actual front/back, IC marking, headers and jumper positions. The pictured adapter is a black multipurpose **no-ZIF** breakout with yellow SPI headers and white power connectors; its schematic and jumper behavior are unknown. The small package left of DM5680 below RXD/TXD is only an inspection candidate until marking/continuity confirms its identity.
2. With the adapter disconnected from the Monitor, establish its header mapping and measure flash-supply voltage **and** CS/SCK/MOSI high levels. A scope can check startup/transient peaks; a DMM confirms static rails. Compare with the identified chip's operating/input limits. A 3V3 label or VCC reading alone is insufficient. Flashrom documents a particular black **ZIF** programmer with 3.3 V flash VCC but near-5 V signals. That example does not prove this no-ZIF board has the same defect. [Official flashrom CH341A/B documentation](https://github.com/flashrom/flashrom/blob/main/doc/supported_hw/supported_prog/ch341ab.rst).
3. Remove Monitor power sources, including built-in USB, and establish the rail/bus connections before attaching programmer power. “Monitor powered off” still requires the flash to receive power. Check flash VCC, other receiver rails, current draw and SPI activity under the proposed single-source arrangement. External flash VCC can partially power attached circuitry and create bus contention. Stop if rail behavior or bus ownership is unresolved. Flashrom's generic powered-board/reset alternatives require board-specific validation and are not established for DM5680. Isolation or removal would be a separate hardware decision. [Official flashrom ISP guidance](https://github.com/flashrom/flashrom/blob/main/doc/user_docs/in_system.rst).
4. After electrical mapping and bus ownership are established, use a reviewed, receiver-only read transport with short leads and reliable contacts. Acquire two independent full 1 MiB arrays, retaining raw files/logs, and compare bytes and SHA-256 with the stock backup. Allow only audited read/ID/status/SFDP operations; omit write-enable, erase, program, protection changes and Monitor-specific GPIO routing. A generic utility's “read” option alone is not an opcode audit. [Flashrom connection/signal troubleshooting](https://github.com/flashrom/flashrom/blob/main/doc/user_docs/misc_notes.rst).

A matching direct read demonstrates external access to the existing stock array under the measured setup. If the receiver CPU is demonstrably inactive, it strengthens evidence that reads do not require running receiver firmware. It does **not** test erase/program, protection handling, interrupted-write recovery, reconnectability after damage, or a cold boot after restoration. Status `00/00` from the built-in route is not a write/recovery test. Recovery remains unproven until separately authorized physical restoration is exercised and verified.
